# 《大勇者》开发计划与内容细分 v1.1

> 本文保留2026-05-27的本地客户端开发拆解，用于追踪已有玩法代码，不再作为联网阶段顺序。
> 联网开发、聊天和拍卖行以[[网页网络游戏改造总案【定案】]] §9及三份联网系统定案为唯一基线。
> 当前定位：网页网络挂机RPG；每名玩家独立地图，只共享聊天和拍卖行。
> 2026-09-16范围确认：后续唯一客户端为Godot Web，只维护浏览器版与服务器，不维护桌面原生版；本文旧技术备选和多槽位入口不再指导新开发，具体边界见[[网页网络游戏改造总案【定案】]] §3.3。

> 设计柱检验：保留已有玩法拆解供源码复用，保护柱2与柱4；单一浏览器交付避免重复维护，符合柱5。

## 二、开发阶段规划

### Phase 0 — 基础框架（预估 1~2 周）

**目标**：搭建项目骨架，确立数据驱动架构，跑通最小可运行循环

| # | 任务 | 细节 | 产出物 |
|---|------|------|--------|
| 0.1 | 技术栈选型与项目初始化 | 确定前端框架（推荐 Godot 4 / Unity / Web）、版本管理、构建流水线 | 项目仓库、CI 配置 |
| 0.2 | 数据架构设计 | 全部游戏数据采用配置表驱动（JSON/CSV → 运行时加载），定义数据热更规范 | 数据加载框架、示例配置表 |
| 0.3 | 存档系统 | 玩家进度序列化/反序列化，支持多存档位，存档版本迁移 | SaveManager 模块 |
| 0.4 | UI 框架与基础组件 | 通用弹窗、Toast、列表、滚动、标签页等组件库 | UI 组件库 |
| 0.5 | 核心游戏循环骨架 | 主菜单→游戏→结算→主菜单的状态机，帧更新/定时器基础设施 | GameStateMachine |
| 0.6 | 日志与调试工具 | 运行时日志面板、战斗回放开关、作弊码入口；行为日志事件总线接口（各系统通过事件总线注册日志，解耦） | DebugTool + ActivityEventBus |

| 难点 | 所属系统 | 风险等级 | 说明 |

## 八、风险与建议

1. **数值平衡是最大风险**：5 品质×5 层×13 套装×20 词条 的组合空间巨大，建议 Phase 3 同步开发 Python 数值模拟器，蒙特卡洛验证 Build 强度分布
2. **自动战斗观感**：全自动战斗容易"无聊"，建议战斗动画节奏控制在 3~5 秒/场，关键数字（暴击/格挡）醒目提示，可加速/跳过
3. **地图扩张需提前验证**：28→128 格的间距约束算法建议先用 Python 原型验证分布合理性，再迁移到引擎
4. **配置表先行**：所有数值先填配置表，运行时加载。不要硬编码任何属性/倍率/价格，方便后期调参不碰代码
5. **离线收益公式需谨慎**：全胜估算可能过于乐观，建议加入胜率系数（基于历史战斗统计）
6. **数值平衡工作流**：AI 负责公式框架+配置表+蒙特卡洛模拟+异常值检测；开发者负责体感反馈+最终拍板。每个 Phase 结束时跑模拟器输出分析报告，迭代到体感舒服为止
7. **联网覆盖**：旧“纯单机、无拍卖行”结论已被[[网页网络游戏改造总案【定案】]]覆盖；首版恢复世界聊天和一口价拍卖行，其余地图进度仍按玩家独立计算
