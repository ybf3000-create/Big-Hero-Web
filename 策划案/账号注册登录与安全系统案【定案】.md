# 账号注册登录与安全系统案 v1.2【定案】

> 本案定义账号申请、密码验证、登录会话、20 人在线名额和账号管理。
>
> 已确认：邀请码注册后自动通过，不收集邮箱/手机，每账号1角色，新设备登录踢旧设备，断线名额保留30秒。完整确认记录见 [[联网规则基线与冲突处理表【已同步】]] §1。

---

## 1. 目标与非目标

| 类型 | 内容 |
|------|------|
| 目标 | 玩家在网页输入账号和密码后登录，选择属于自己的角色进入游戏 |
| 目标 | 密码泄露、暴力尝试、会话被盗和越权访问有明确防线 |
| 目标 | 同时在线人数严格不超过 20，断线可在短时间内恢复 |
| 目标 | 邀请码、注册、封禁、删号和管理员重置密码均有成功与失败记录 |
| 非目标 | 首版不做第三方社交账号登录 |
| 非目标 | 首版不做跨服账号、游客账号和账号交易 |
| 非目标 | 账号密码不用于任何游戏内展示；玩家只看到角色名 |

> 设计柱检验：账号系统本身不增加养成压力；它保护玩家积累和交易资产，支撑柱1“挂机爽感”、柱5“不肝不氪”和恢复后的柱6“玩家经济”。

## 2. 术语与状态

### 2.1 固定名称

| 名称 | 唯一定义 |
|------|---------|
| 登录账号 | 玩家登录时输入的唯一标识，不等于角色名，不公开展示 |
| 账号申请 | 玩家提交登录账号及必要验证信息的行为 |
| 账号状态 | `正常`、`封禁`、`已删除` |
| 邀请码状态 | `可用`、`已使用`、`已撤销`、`已过期` |
| 游戏会话 | 登录成功后由服务端建立的一次在线连接 |
| 会话令牌 | 证明当前请求属于某个游戏会话的高熵随机凭证 |
| 记住登录令牌 | 仅用于当前浏览器免输密码恢复登录的长期随机凭证，不是密码密文 |
| 在线名额 | 允许账号进入角色选择和游戏的并发容量，共 20 个 |
| 角色槽 | 每个账号固定1个角色位置，不扩容 |

### 2.2 账号状态迁移

```text
提交注册
  ├─ 邀请码可用且账号资料合法 → 原子消耗邀请码，账号直接变为正常
  └─ 邀请码无效/资料不合法/事务失败 → 不创建账号

正常
  ├─ 管理员按小时封号 → 封禁（最长72小时）
  ├─ 管理员删号 → 已删除并撤销全部会话
  └─ 保持正常

封禁
  ├─ 到达服务端结束时间 → 自动恢复正常
  └─ 管理员提前解除 → 恢复正常
```

禁止从客户端直接指定账号状态。每次迁移必须记录操作者、原因、服务端时间和旧/新状态。

## 3. 邀请码注册

| 规则 | 已确认内容 |
|------|-----------|
| 注册入口 | 玩家填写邀请码、登录账号、密码和确认密码 |
| 审批 | 不需要；邀请码校验成功后账号自动通过 |
| 邀请码使用次数 | 每个邀请码最多成功注册1个账号 |
| 邀请码生成 | 管理员生成；界面显示是否可用、生成时间和使用时间 |
| 邀请码撤销 | 未使用时可撤销；已使用后不可再次使用 |
| 邀请码过期 | 默认不过期；管理员可主动撤销 |
| 邮箱/手机 | 不收集、不验证 |

审批的含义原本是“玩家提交账号申请后，管理员逐个点击同意”。本项目不采用该流程；持有有效邀请码就是注册资格。

## 4. 输入规则

### 4.1 登录账号

| 项目 | 推荐值 | 边界处理 |
|------|--------|---------|
| 长度 | 4~20 个 ASCII 字符 | 少于 4 或超过 20 时拒绝 |
| 字符 | 小写字母、数字、下划线；首字符必须为字母 | 服务端转小写后校验 |
| 唯一性 | 全服不区分大小写唯一 | 已占用时返回通用失败提示 |
| 展示 | 只在本人账号设置和后台显示 | 聊天、拍卖展示角色名 |
| 保留词 | `admin`、`system`、`gm` 等保留 | 命中时拒绝 |

### 4.2 密码

| 项目 | 推荐值 | 边界处理 |
|------|--------|---------|
| 长度 | 10~64 个字符 | 少于 10 或超过 64 时拒绝 |
| 允许字符 | 可打印字符，不强制特殊字符组合 | 只含空白、常见弱密码时拒绝 |
| 确认 | 注册和改密时输入两次 | 两次不一致时不提交 |
| 存储 | Argon2id 加盐哈希 | 永远不存明文或可逆密文 |
| 日志 | 禁止记录密码、密码哈希、完整会话令牌 | 即使调试模式也禁止 |

长度按 Unicode 字符数校验，同时限制 UTF-8 最大 256 字节，避免极端输入消耗。

### 4.3 角色名

| 项目 | 规则 | 失败处理 |
|------|------|---------|
| 唯一性 | 全服唯一 | 已存在时拒绝并要求换名 |
| 允许字符 | 汉字、英文字母、数字 | 空格、标点、表情和其他字符拒绝 |
| 长度权重 | 汉字计2，字母/数字计1，总权重1~14 | 权重为0或超过14时拒绝 |
| 最大示例 | 7个汉字，或14个字母/数字 | 混合名称按权重累计 |
| 规范化 | 英文字母保留显示大小写，但唯一性比较不区分大小写 | 大小写变体视为重名 |

账号名与角色名分离。`client/scripts/save_manager.gd`已同步为上述权重算法；联网服还必须通过数据库唯一索引保证全服不重名。

## 5. 账号申请流程

### 5.1 通用流程

```text
Step 1 玩家填写账号、密码、确认密码
Step 2 填写一次性邀请码
Step 3 客户端只做即时格式提示
Step 4 服务端重新校验全部字段和提交频率
Step 5 服务端在一个事务内创建申请记录
  ├─ 创建成功 → 邀请码标记已使用，账号直接正常，可立即登录
  └─ 创建失败 → 不创建半成品账号，返回稳定错误码
```

### 5.2 成功与失败

| 场景 | 处理 | 玩家提示 |
|------|------|---------|
| 账号格式有效、未占用且邀请码有效 | 创建账号 | “账号创建成功” |
| 账号已存在 | 不创建 | “该账号不可用” |
| 两次密码不一致 | 不发送或服务端拒绝 | “两次输入的密码不一致” |
| 邀请码有效 | 原子消耗邀请码并创建账号 | “账号创建成功” |
| 邀请码无效/过期/已使用 | 不创建、不泄露邀请码详情 | “邀请码无效” |
| 提交过快 | 限流，不创建 | “尝试过于频繁，请稍后再试” |
| 数据库不可用 | 整体失败 | “服务暂时不可用，请稍后重试” |
| 响应丢失后重复提交 | 依据申请编号返回第一次结果 | 不重复创建账号/消耗邀请码 |

### 5.3 容量边界

| 边界 | 处理 |
|------|------|
| 注册账号数为 0 | 管理员仍可进入本机管理工具生成首批邀请码 |
| 注册账号总数 | 不受20人限制；20只限制同时在线，注册数量由邀请码控制 |
| 同一邀请码 | 最多成功使用1次，事务内锁定 |
| 同一账号并发注册 | 唯一索引保证只有一笔成功 |

## 6. 邀请码验证与自动通过

```text
服务端收到注册请求
  ├─ 邀请码状态=可用且账号名未占用
  │    → 同一事务创建账号、标记邀请码已使用、写审计记录
  │    → 事务成功后账号立即可登录
  └─ 邀请码不存在/已用/已撤销，或账号名已占用
       → 整体失败，不改变邀请码和账号表
```

| 边界 | 处理 |
|------|------|
| 同一邀请码被两人同时提交 | 数据库锁定邀请码，只有第一笔事务成功 |
| 管理员误发邀请码 | 使用前可撤销；已使用后不能删除对应账号，只能单独删号 |
| 注册响应丢失 | 玩家可直接尝试登录；重复注册不会消耗第二次 |
| 邀请码为空 | 拒绝，不进入密码哈希计算 |

不建立“待审批”账号状态，也不建立邮箱验证、手机验证或申请队列。

## 7. 登录与密码验证

### 7.1 登录流程

```text
Step 1 接收登录账号和密码
Step 2 检查来源限流，但不透露账号是否存在
Step 3 读取账号；不存在时执行等时长的假哈希校验
Step 4 使用 Argon2id 校验密码
Step 5 检查账号状态
Step 6 检查同账号会话策略与在线名额
  ├─ 可进入 → 创建会话并占用名额
  └─ 不可进入 → 不创建游戏会话
Step 7 返回角色列表和会话信息
```

### 7.2 失败分支

| 原因 | 对外提示 | 内部处理 |
|------|---------|---------|
| 账号不存在/密码错误 | 统一为“账号或密码错误” | 记录失败次数，不记录密码 |
| 封禁 | “账号已封禁，剩余XX小时” | 不占在线名额；最长72小时 |
| 已删除 | 与账号不存在使用相同提示 | 不创建会话 |
| 服务器已满 | “服务器人数已满，请稍后登录” | 身份验证完成但不创建游戏会话、不排队 |
| 客户端版本不兼容 | “游戏已更新，请刷新页面” | 不占名额 |
| 服务异常 | “暂时无法登录” | 不把内部堆栈返回客户端 |

### 7.3 防暴力尝试

| 维度 | 限制 | 超限处理 |
|------|------|---------|
| 单 IP | 10 次/10 分钟 | 冷却 15 分钟 |
| 单账号 | 5 次/10 分钟 | 冷却 15 分钟 |
| 连续失败 | 第 5 次起递增延迟 | 成功登录后清零短期失败计数 |
| 公开注册模式 | 超限后可增加验证码 | 邀请小服默认不引入第三方验证码 |

性能：密码哈希参数需在部署机器上测量，使单次校验约 100~300ms；并发校验队列设硬上限，避免登录洪泛拖垮游戏循环。`[需与程序确认]`

## 8. 会话与 20 人在线名额

### 8.1 会话令牌

| 项目 | 推荐规则 |
|------|---------|
| 生成 | 32 字节密码学安全随机数 |
| 传输 | 当前只允许经ZeroTier加密私网内的同源HTTP/WS传输；URL中禁止携带令牌；若改为公网必须升级HTTPS/WSS |
| 存储 | 服务端只存摘要；客户端只在当前页面内存持有 |
| 空闲超时 | 30 分钟无有效请求后失效 |
| 最长有效期 | 7 天；页面持续在线时由心跳续期 |
| 登出 | 立即撤销当前令牌并释放在线名额 |
| 改密/封禁 | 改密保留执行改密的当前会话，撤销全部记住登录令牌；管理员重置、封禁或删号撤销全部长期令牌和数据库会话 |

### 8.2 记住登录状态

玩家在登录页勾选“记住登录状态（仅限当前浏览器）”后，服务端签发独立的记住登录令牌。浏览器不保存账号密码，也不保存任何可逆密码密文；旧版本产生的`user://login_credentials.cfg`在新版首次启动时删除。

| 场景 | 成功处理 | 失败/边界处理 |
|------|----------|---------------|
| 未勾选 | 只建立当前游戏会话；密码在请求完成后从输入框清空 | 不创建长期令牌，并清除当前站点已有的记住登录Cookie |
| 勾选并登录成功 | CSPRNG生成令牌；数据库只存SHA-256摘要；浏览器保存`HttpOnly`、`SameSite=Strict` Cookie | 密码校验、封禁检查或20人容量检查失败时不创建长期令牌 |
| 再次打开网页 | 服务端校验摘要、账号状态和在线容量，成功后建立新游戏会话并轮换长期令牌 | 无Cookie时显示普通登录页；令牌无效、过期、改密或封禁时要求重新登录，下次密码登录会替换或清除旧Cookie |
| 新浏览器勾选并登录 | 新长期令牌生效，同账号旧长期令牌立即撤销 | 同账号最多1个有效记住登录令牌，不允许无限累积 |
| 主动退出 | 撤销长期令牌并清除Cookie | 即使游戏会话刚好失效，也先撤销可识别的长期令牌 |
| 修改/重置密码、封号、删号 | 撤销该账号全部长期令牌 | 下次打开网页必须重新输入有效密码 |

记住登录令牌每次成功恢复后立即轮换，有效期从本次恢复起重新计算30天。它只用于换取新的游戏会话，不直接执行角色、资产或拍卖操作。ZeroTier负责链路加密；若绕过ZeroTier直接使用公网HTTP，密码和令牌均不满足本案安全要求，服务端不得按公网方案交付。

> 设计柱检验：免重复输入降低熟人小服的登录摩擦，长期令牌不接触游戏资产且随改密、封禁和删号撤销，兼顾柱5的低负担与柱6的玩家经济安全。

### 8.3 心跳与断线恢复

```text
每 10 秒发送一次心跳
  ├─ 服务端收到 → 更新最后活动时间
  └─ 连续 30 秒未收到 → 标记断线，释放在线名额

断线后 30 秒内携带有效会话重连
  ├─ 原会话尚保留 → 恢复角色快照，不重复计算离线收益
  └─ 原会话已过期 → 重新登录；离线收益从服务端断线时间计算
```

### 8.4 同账号多设备

新设备使用正确账号密码登录后，新会话生效并撤销旧会话；旧端收到“账号已在其他设备登录”后断开。切换过程中同一账号最多占1个在线名额，同一角色始终只有一个可写会话。

## 9. 角色归属与槽位

| 规则 | 成功 | 失败 |
|------|------|------|
| 读取角色列表 | 只返回当前账号拥有的角色 | 越权角色编号返回“角色不存在” |
| 创建角色 | 账号尚无角色且名称通过校验时创建 | 已有角色、名称冲突或格式错误时拒绝 |
| 选择角色 | 原子获得角色写锁并加载快照 | 角色已被旧会话占用时先撤销旧会话 |
| 管理员删号 | 撤销会话、结束或退回拍卖托管、逻辑删除账号和角色 | 有未完成事务时等待完成或回滚后再删 |

现有3个本地槽位不迁移到联网账号。联网版每账号固定1个角色；旧本地槽位只保留给开发回归模式。

## 10. 管理员重置密码与改密

玩家忘记密码时私下联系管理员。管理员生成一次性临时密码并告知玩家；临时密码首次成功登录后必须修改，成功改密后撤销该账号全部旧会话。管理员不能查看旧密码。

失败分支：账号不存在或已删除时不生成临时密码；临时密码已使用或被再次重置后立即失效；管理员工具不得把临时密码写入日志。

## 11. 管理操作与审计

| 操作 | 最低权限 | 审计字段 |
|------|---------|---------|
| 生成/撤销邀请码 | 管理员 | 操作者、邀请码摘要、时间、结果 |
| 按小时封号/解封 | 管理员 | 原因、期限、旧/新状态；最长72小时 |
| 按小时禁言/解禁 | 管理员 | 原因、期限、旧/新状态；最长72小时 |
| 删除账号 | 管理员 | 二次确认、目标、原因、时间、结果 |
| 重置密码 | 管理员 | 只记动作，不记临时密码 |
| 强制下线 | 管理员 | 会话编号、原因 |
| 查看登录记录 | 管理员 | 查询操作者与条件 |

管理员不做账号逐个审批，也不提供发金币/发装备功能。审计记录保留180天，达到保留期后按月批量删除或归档；禁止玩家客户端访问。

## 12. 数据结构概要

| 表 | 关键字段 | 关键约束 |
|----|---------|---------|
| `accounts` | id、login_name、password_hash、status、created_at | `login_name` 规范化后唯一 |
| `invite_codes` | code_hash、status、created_at、used_by_account_id | 邀请码摘要唯一；最多使用一次 |
| `sessions` | id_hash、account_id、last_seen_at、expires_at、revoked_at | 只存令牌摘要 |
| `remembered_logins` | token_hash、account_id、expires_at、revoked_at | 只存长期令牌摘要；每账号最多1条有效记录 |
| `login_attempts` | login_key_hash、ip_hash、result、created_at | 不存输入密码 |
| `characters` | id、account_id、name、name_weight、revision | account_id唯一；规范化角色名全服唯一 |
| `account_audit_log` | actor_id、target_id、action、reason、created_at | 仅追加，不覆盖 |

隐私边界：不收集邮箱和手机号。登录IP只用于短期限流和故障排查，不在玩家界面展示。

## 13. 随机算法

账号系统不使用游戏随机算法。所有验证码、邀请码和会话令牌必须使用操作系统提供的密码学安全随机源：

```text
原始随机：CSPRNG 生成至少 256 bit
对外编码：Base64URL，不包含可混淆空格
数据库：只存 SHA-256(原始令牌) 与用途、过期时间
校验：摘要常量时间比较
成功：事务内标记已使用
失败：不改变账号状态
```

邀请码若需要人工输入，可使用去除易混淆字符的字母数字表；至少 128 bit 熵，最多校验 1 次数据库记录，不进行随机重试生成。唯一键冲突时最多重新生成 3 次，仍失败则中止并记录异常。

## 14. 性能与容量

| 项目 | 上限/策略 |
|------|----------|
| 同时在线 | 20 个账号会话 |
| 单账号有效游戏会话 | 1 个 |
| 单账号有效记住登录令牌 | 1 个；新令牌撤销旧令牌 |
| 记住登录有效期 | 每次成功恢复后30天；过期必须重新输入密码 |
| 角色槽 | 每账号1个 |
| 登录请求正文 | 最大 4KB |
| 账号申请请求正文 | 最大 16KB |
| 角色列表 | 固定最多1条，不分页 |
| 审计查询 | 每页 50 条，最大 200 条/次 |
| 登录超时 | 接口目标 5 秒内明确成功或失败 |

数据库查询均按规范化账号名、账号状态和会话摘要建立索引。20 人规模不需要缓存账号密码哈希，也禁止把密码验证结果长期缓存。

## 15. 验收用例

| # | 用例 | 预期 |
|---|------|------|
| A01 | 正确账号密码登录 | 创建 1 个会话，占用 1 个名额 |
| A02 | 错误密码登录 | 通用失败提示，不创建会话 |
| A03 | 账号不存在 | 与错误密码相同的对外表现 |
| A04 | 20 人已在线时第 21 人登录 | 不进入游戏，不超过 20 |
| A05 | 同一账号并发两次登录 | 严格按已确认策略，只保留一个可写会话 |
| A06 | 同一注册请求重复发送 | 只创建一个账号/只消耗一次邀请码 |
| A07 | 修改密码 | 旧密码和旧会话全部失效 |
| A08 | 越权读取他人角色 | 拒绝且不泄露角色是否存在 |
| A09 | 心跳中断 30 秒 | 释放名额，记录服务端断线时间 |
| A10 | 会话重连 | 不重复发放离线收益 |
| A11 | 数据库在注册中断开 | 无半成品账号 |
| A12 | 日志检查 | 不含密码、密码哈希和完整令牌 |
| A13 | 勾选后刷新网页 | 不再次输入密码即可恢复；长期令牌完成轮换 |
| A14 | 未勾选或主动退出 | 浏览器不保留密码，刷新后显示登录页 |
| A15 | 改密、管理员重置、封号或删号 | 全部记住登录令牌失效 |
| A16 | 新浏览器重新勾选 | 旧浏览器的长期令牌失效；同账号有效长期令牌不超过1个 |

## 16. 设计柱检验

| 决策 | 设计柱 | 检验 |
|------|--------|------|
| 账号与角色名分离 | 柱5 | 玩家无需用公开昵称承担登录安全风险 |
| 短时断线恢复 | 柱1 | 浏览器网络波动不打断挂机收益体验 |
| 单账号单写会话 | 柱6 | 防止同一资产被两个客户端并发消费或交易 |
| 找回后撤销旧会话 | 柱6 | 降低盗号后继续转移资产的风险 |
| 记住登录不保存密码 | 柱5、柱6 | 保留便捷登录，同时避免在浏览器磁盘留下明文或可逆密码 |
