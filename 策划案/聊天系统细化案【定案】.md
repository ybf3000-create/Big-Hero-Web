# 聊天系统细化案 v1.1【定案】

> 本案面向最大同时在线 20 人的单服网页游戏。
>
> 已确认：首版只有世界频道和只读系统频道；世界消息保存7天；支持玩家屏蔽与管理员最长72小时禁言；不做私聊、交易频道、拍卖分享、举报和敏感词过滤。完整记录见 [[联网规则基线与冲突处理表【已同步】]] §1。

---

## 1. 设计目标

| 目标 | 说明 |
|------|------|
| 轻量交流 | 玩家挂机时可以交流，不要求离开主游戏界面 |
| 交易协作 | 为拍卖行提供询价和供求沟通，但实际资产只在拍卖行流转 |
| 身份可信 | 所有消息由服务端绑定发送角色，客户端不能伪造名字和系统消息 |
| 可治理 | 支持个人屏蔽和管理员按小时禁言 |
| 低干扰 | 聊天不是强制玩法，不弹窗阻断掷骰和战斗 |

> 设计柱检验：聊天增强柱6“玩家经济”的市场沟通，但默认不影响自动挂机，保持柱1“挂机爽感”和柱5“不肝不氪”。

---

## 2. 频道规则

| 频道 | 可发送者 | 可见范围 | 推荐首版 |
|------|---------|---------|---------|
| 世界 | 正常且未禁言的在线角色 | 全服在线玩家 | 可读写 |
| 系统 | 仅服务端和管理员工具 | 与事件相关的玩家或全服 | 玩家只读 |

私聊、交易、队伍和公会频道均不创建。拍卖订单不能分享到世界频道。

---

## 3. 消息结构与固定名称

| 字段 | 说明 |
|------|------|
| 消息编号 | 服务端生成的全局唯一编号，用于去重和断线补发 |
| 频道 | 只允许 `world` 或 `system` |
| 发送账号编号 | 仅服务端和后台使用，不下发给普通玩家 |
| 发送角色编号 | 服务端校验角色归属 |
| 发送角色名 | 服务端从角色记录读取，不接受客户端自报 |
| 正文 | 清洗后的纯文本 |
| 服务端时间 | 统一以服务器时间生成 |
| 消息类型 | 普通、系统通知、管理公告 |
| 状态 | 正常、已过期 |

“行为日志”和“聊天消息”是两套数据：行为日志记录玩家自己的游戏行为，见 [[行为日志【定案】]] §2；聊天记录玩家之间的信息，不写入角色存档。

---

## 4. 输入与显示规则

| 项目 | 推荐规则 | 失败处理 |
|------|---------|---------|
| 消息长度 | 去除首尾空白后 1~120 个 Unicode 字符，且 UTF-8 不超过 480 字节 | 为空或超长时拒绝，保留输入框内容 |
| 换行 | 单条消息最多 3 行 | 超过时拒绝或在输入时阻止 |
| 富文本 | 只发送纯文本，不解析玩家输入的 BBCode/HTML/Markdown | 显示前统一转义 |
| 链接 | 首版不做可点击外链 | 以普通文本显示或按确认规则拦截 |
| 表情 | 允许普通 Unicode 表情 | 仍计入字符和字节上限 |
| 角色名 | 显示服务端当前角色名 | 客户端传入的名字字段被忽略 |
| 时间 | 显示玩家本地时区，悬停可看完整时间 | 排序始终使用服务端时间和消息编号 |

浏览器端必须保证长单词、连续数字和 URL 在聊天区域内自动换行，不能撑开主界面或覆盖游戏按钮。

## 5. 发送流程

### 5.1 普通频道

```text
Step 1 玩家选择频道并输入正文
Step 2 客户端本地检查空白和长度，仅用于即时提示
Step 3 发送 `client_message_id + channel + body`
Step 4 服务端依次校验：
  会话 → 角色 → 频道权限 → 禁言 → 频率 → 长度 → 内容规则
Step 5 服务端分配消息编号和时间并写入记录
  ├─ 成功 → 广播给频道成员，并向发送者确认
  └─ 失败 → 不广播，返回错误码；输入内容保留供修改
```

### 5.2 去重

`client_message_id` 在同一会话内唯一。网络超时后用相同编号重试时，服务端返回第一次发送结果，不生成第二条消息。

### 5.3 成功和失败分支

| 场景 | 结果 | 玩家反馈 |
|------|------|---------|
| 正常发送 | 持久化后广播 | 消息由“发送中”变为“已发送” |
| 网络未确认 | 暂不重复显示 | 显示“发送中”，可自动以同编号重试一次 |
| 已断线 | 不发送 | “已断开连接，正在重连” |
| 被禁言 | 不发送 | 显示禁言原因和到期时间 |
| 频道无权限 | 不发送 | “无法在该频道发言” |
| 触发限流 | 不发送 | “发送太快，请稍后” |
| 内容格式不安全 | 不做词库判断；只按§4拒绝超长、空白或无法安全显示的输入 | 给出格式提示，不广播 |
| 服务端写入失败 | 不广播 | “发送失败，请重试” |
| 重复请求 | 返回原消息 | 聊天区只出现一次 |

## 6. 频率与容量边界

### 6.1 发送限制

| 维度 | 限制 |
|------|------|
| 世界频道 | 每个角色1条/秒，10秒最多5条 |
| 完全相同正文 | 30 秒内最多 2 次 |
| 系统公告 | 管理员工具每 10 秒最多 1 条 |

超限时丢弃本次消息但不延长禁言；持续异常可由后台产生风控记录。

### 6.2 客户端容量

| 边界 | 处理 |
|------|------|
| 当前频道 0 条 | 显示空状态，不显示假消息 |
| 内存消息达到 200 条/频道 | 删除最旧的本地显示项，不删除服务端记录 |
| 首次打开频道 | 加载最近 50 条 |
| 向上翻历史 | 每页 50 条，按游标加载 |
| 单次最多加载 | 200 条，之后继续分页 |
| 未读数 | 每频道显示，`99+` 封顶展示 |

### 6.3 20 人峰值与性能

按 20 人每人 1 条/秒估算持续上限 20 条/秒；压测按 100 条/秒、持续 10 秒的突发验证。单体服务按频道一次构造消息，再向订阅连接发送，避免为每名玩家重复格式化和重复查库。

## 7. 历史消息与断线恢复

### 7.1 留存规则

| 类型 | 推荐留存 | 说明 |
|------|---------|------|
| 世界 | 7 天 | 20 人服足以查看近期交流，存储压力低 |
| 系统公告 | 30 天 | 便于玩家查找维护和成交信息 |

### 7.2 断线补发

```text
客户端保存各频道最后收到的消息编号
重连时提交最后编号
  ├─ 缺失消息仍在留存期且数量 ≤ 200 → 按顺序补发
  ├─ 缺失数量 > 200 → 只返回最近 200 条并标记“部分历史未显示”
  └─ 已超出留存期 → 从当前最新窗口开始
```

## 8. 首版明确不做

| 功能 | 处理 |
|------|------|
| 私聊 | 无入口、无接口、无离线私信记录 |
| 交易频道 | 不建立；玩家可在世界频道自行交流，但不能发送结构化拍卖卡片 |
| 拍卖分享 | 拍卖界面不提供“分享到聊天”按钮 |
| 举报 | 首版不做举报队列 |
| 敏感词 | 首版不拦截、不替换；熟人小服由屏蔽和管理员禁言处理 |

若未来新增上述任一功能，必须升版本文并补充成功/失败、容量、留存和权限规则，不能只增加客户端按钮。

---

## 9. 屏蔽与禁言

### 9.1 个人屏蔽

| 规则 | 推荐值 |
|------|--------|
| 屏蔽上限 | 每账号 100 个角色 |
| 生效范围 | 世界频道不显示被屏蔽者普通消息 |
| 系统消息 | 不可屏蔽 |
| 解除屏蔽 | 立即生效，不补发屏蔽期间普通消息 |
| 达到上限 | 拒绝新增，提示先移除旧记录 |

### 9.2 禁言

| 状态 | 处理 |
|------|------|
| 未禁言 | 可在世界频道发送 |
| 临时禁言 | 管理员输入1~72小时；到期前不可发送，但可读世界和系统消息 |
| 输入0、负数或超过72小时 | 拒绝操作并提示合法范围 |
| 禁言到期 | 服务端按时间自动恢复，不依赖客户端定时器 |
| 管理员提前解除 | 立即恢复发送权限，并记录审计 |

### 9.3 敏感词与举报

首版不启用敏感词词库，也不提供举报按钮。消息仍必须按 §4 作为纯文本转义，防止注入；内容纠纷由玩家屏蔽或私下联系管理员处理。

---

## 10. 系统消息

| 来源 | 示例 | 接收范围 |
|------|------|---------|
| 登录服务 | 服务器即将维护 | 全服或目标玩家 |
| 拍卖行 | 订单成交、到期、取消 | 相关玩家 |
| 账号管理 | 禁言、强制下线 | 目标玩家 |
| 管理公告 | 活动或规则通知 | 全服 |

客户端不得发送 `system` 类型。服务端为每类系统消息使用固定模板和结构化参数，客户端负责本地化显示，避免管理员输入可执行富文本。

## 11. UI 交互草案

```text
主游戏界面右侧或底部聊天栏
┌───────────────────────────┐
│ [世界] [系统]                │
├───────────────────────────┤
│ 12:30 角色甲：有人出火焰套吗 │
│ 12:31 角色乙：我去拍卖行看看   │
│ 12:32 系统：你的订单已成交     │
├───────────────────────────┤
│ [输入消息……              ] [发送] │
└───────────────────────────┘
```

| 交互 | 规则 |
|------|------|
| 收起面板 | 不停止接收；只累计未读数 |
| 战斗期间 | 可查看和输入，不暂停自动战斗 |
| 点击角色名 | 提供屏蔽/解除屏蔽入口 |
| Enter | 聚焦输入框时发送；未聚焦时不抢占游戏操作 |
| 发送失败 | 原文保留，错误显示在输入区附近 |

## 12. 数据结构概要

| 表 | 关键字段 | 关键索引/约束 |
|----|---------|-------------|
| `chat_messages` | id、channel、sender_character_id、body、type、created_at、status | `(channel, id DESC)` |
| `chat_blocks` | owner_account_id、blocked_character_id、created_at | 两字段唯一，最多 100 |
| `chat_mutes` | account_id、reason、starts_at、ends_at、operator_id | 查询当前有效禁言 |

清理任务每日执行一次，每批最多删除 1,000 条到期记录；失败时下次重试，不影响实时聊天。

---

## 13. 随机算法说明

聊天内容投递、屏蔽、禁言、限流和历史分页均为确定性规则，不使用随机算法。

若未来增加“随机频道昵称”或“抽取在线玩家”等功能，必须另案定义随机池、权重、去重和重试上限；本版不预留隐藏随机行为。

## 14. 验收用例

| # | 用例 | 预期 |
|---|------|------|
| C01 | 20 人同时在世界频道发送 | 所有有效消息有唯一编号且顺序稳定 |
| C02 | 同一消息超时重试 | 只出现一次 |
| C03 | 客户端伪造系统消息/角色名 | 服务端忽略伪造字段并拒绝越权类型 |
| C04 | 超长、空白、富文本消息 | 不广播，客户端布局不被破坏 |
| C05 | 触发限流 | 其他玩家看不到被拒消息 |
| C06 | 屏蔽角色 | 其普通消息不显示，系统消息仍显示 |
| C07 | 禁言到期 | 服务端自动恢复发言权限 |
| C08 | 断线后补发 | 不重复、不乱序，最多补 200 条 |
| C09 | 尝试调用私聊、交易频道或拍卖分享接口 | 服务端返回“不支持的功能”，不创建消息 |
| C10 | 数据库暂时不可用 | 消息明确失败，不出现“看似发送但未记录” |

## 15. 设计柱检验

| 决策 | 设计柱 | 检验 |
|------|--------|------|
| 聊天不暂停挂机 | 柱1、柱5 | 社交不会降低自动成长效率 |
| 不做拍卖分享 | 柱1、柱5 | 聊天保持轻量，不引入广告刷屏或额外交易入口 |
| 限流、屏蔽和禁言 | 柱5、柱6 | 降低骚扰和刷屏，保护小服交流质量 |
| 历史按需分页 | 柱1 | 不因聊天记录拖慢主游戏 |
