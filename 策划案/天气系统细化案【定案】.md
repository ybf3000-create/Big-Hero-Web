# 天气系统细化案 v0.6【定案】

> 对应：GDD §3 战斗系统（天气对战斗的影响层）
> 版本：v0.5 | 日期：2026-05-25 | 状态：待 ybf 确认
> 用途：定义天气的生成、轮换、对战斗的影响及其视觉表现。

---

## 1. 天气总览

### 1.1 基础规则

```
天气是每个玩家独立计算的效果——每个人的天气轮换互不干扰。
天气不影响地图走圈，仅在进入战斗后附加额外效果。
大部分情况下天气无效果（晴天），特殊天气为战斗增加变数。
```

### 1.2 设计柱检验

> **柱3（Boss解锁驱动）**：天气系统作为 Boss6 解锁的新系统，持续给玩家"新玩具"。
> **柱1（挂机爽感）**：被动影响战斗，无需玩家操作。
> **柱5（不肝不氪）**：玩家不控制天气，策略只在"当前天气下要不要调整 Build"。
> **个性化维度**：每人天气独立，不同玩家在同一时间感受不同天气，社交上可交流"我今天运气好，一直晴天"。

> **设计意图**：晴天占 58% 确保"大部分时间无影响"。北极光作为极稀有的增益天气，权重仅 2%，给玩家"撞大运"的惊喜感。所有属性修正（命中率/闪避率/格挡率）均使用**乘法修正**而非减法，避免低基础属性时出现负数。

### 2.2 乘法修正说明（规则3 极限情况）

```
为确保低基础属性下天气修正不会产生负数，所有命中率/闪避率/格挡率
天气效果均采用乘法（乘算），而非减法（加算）。

例（大雾下）：
  ├─ 玩家命中率 100%  → 100% × 0.8 = 80%  ✅
  ├─ 玩家命中率 20%   → 20% × 0.8 = 16%   ✅（减法则 = -20%  ❌）
  └─ 玩家命中率 10%   → 10% × 0.8 = 8%    ✅（减法则 = -30%  ❌）

不设下限保护：乘法修正后即为最终值，命中率/闪避率/格挡率可低至 0%（纯粹运气差设计）。
例（大雾下）：
  ├─ 命中率 10% → 10% × 0.8 = 8%
  ├─ 命中率 5%  → 5% × 0.8 = 4%
  └─ 命中率 0%  → 0% × 0.8 = 0%（脸黑到极致）
```

> 规则3（极限情况）：乘法修正后命中率/闪避率/格挡率最低无保底，可降至 0%。纯粹运气差的设计——低命中率遇上大雾就真打不中了。

### 2.3 权重算法

```
[每次天气变更时]

Step 1 — 构建权重池（8 种可用天气，权重见上表）
Step 2 — 取随机数 R = [0, 100)
Step 3 — 按权重序累加，落到哪个区间就取哪个天气
Step 4 — 若抽到与当前天气相同 → 重新抽取 1 次（不连续）
Step 5 — 若第 2 次仍相同 → 不再重抽，允许连续（防死循环）

示例权重累加区间（v0.3）：
  晴天   = [0, 58)    → 58% 概率
  雷雨天  = [58, 68)   → 10% 概率
  细雨   = [68, 76)   → 8% 概率
  大雾   = [76, 83)   → 7% 概率
  暴风雪  = [83, 90)   → 7% 概率
  烈日   = [90, 95)   → 5% 概率
  沙暴   = [95, 98)   → 3% 概率
  北极光  = [98, 100)  → 2% 概率
```

> 规则6（随机明确）：权重累加法，不放回式连续检查（最多 1 次重试），保底机制见 Step 5。

## 3. 天气变更机制

### 3.1 变更驱动：骰子次数（大地图移动次数）

```
天气变更不再基于现实时间，而是基于玩家的"骰子次数"。

[术语定义]
  骰子次数 = 玩家在大地图上掷骰子的次数
  每次掷1颗骰子（数值1~6）并按点数移动 → 骰子次数 +1
  注意：骰子次数 ≠ 战斗次数，也 ≠ 移动格子数
  - 非战斗格（空地/宝箱/命运/休息/商店等）踩到后也消耗骰子次数
  - 战斗期间不消耗骰子次数（战斗是在格子事件内发生的，不影响地图掷骰）

[核心规则]
  1. 玩家每次在大地图掷1次骰子，骰子计数器 +1
  2. 每轮天气持续期间，系统预设一个随机阈值 T ∈ [1, 15]
  3. 当骰子计数器 ≥ T 时，触发天气变更
  4. 变更后计数器归零，重新生成本轮的 T（再次随机 1~15）
  5. 前 10 次天气变更为晴天（初始缓冲期，见 §3.2）

例：
  解锁天气后首次骰子次数阈值 = 7
  第 1～7 次掷骰 → 晴天
  第 7 次掷骰后 → 触发首次天气变更 → 强制为晴天（第 1 次缓冲）
  新阈值 = 12
  第 8～19 次掷骰 → 晴天（仍在缓冲期内）
  第 19 次掷骰后 → 第 2 次变更 → 强制为晴天
  ... 直到第 10 次变更完成后，第 11 次起按权重随机
```

> 规则6（随机明确）：阈值 T ∈ [1, 15] 为均匀随机整数，每次变更后重新抽取。最小 1 意味着"下一次掷骰就变更"，最大 15 意味着"最多连掷 15 次骰子同一天气"。

### 3.2 初始缓冲期（规则3 极限情况）

```
[前 10 次天气变更强制为晴天]

目的：让玩家刚解锁天气系统时有充足适应期，不会一上来就遇到雷雨天被打懵。

规则：
  1. 玩家解锁天气系统后，维护一个缓冲计数器（初始 = 10）
  2. 每次触发天气变更时：
     └─ 若缓冲计数器 > 0 → 本次变更为晴天，计数器 -1
     └─ 若缓冲计数器 = 0 → 后续按正常权重随机
  3. 缓冲期结束后不可逆转

极值：
  - 缓冲期最长：10 次变更 × 平均 8 次掷骰/次 ≈ 80 次掷骰 的晴天
  - 缓冲期最短：10 次变更 × 阈值 1 次/次 = 10 次掷骰 的晴天
```

### 3.3 边界情况（规则3）

```
[骰子计数器边界]
  - 阈值 T 最小 1 → 可能上一次掷骰后，下一次掷骰立即再次变更
  - 阈值 T 最大 15 → 同一天气最长持续 15 次掷骰

[新玩家解锁后]
  - 解锁后立刻掷第 1 次骰子 → 骰子计数器从 0 开始，等于当前阈值时才触发
  - 若阈值 = 1，则第 1 次掷骰后就触发变更→晴天（缓冲有效）

[天气尚未解锁的玩家]
  - 始终为晴天，不触发任何变更逻辑，骰子计数器不生效
```

### 3.4 术语说明

```
[一圈]
  定义：玩家每次路过或到达 🏠起点（勇者之家）即算完成一圈。
  - 瞬移路过起点也算完成一圈
  - 走过最后1格回到位置0 = 到达起点 = 完成1圈
  - 持续效果标注"持续1圈"= 下次到达/路过起点时效果结束

[骰子次数]
  定义：玩家在大地图上掷骰子的总次数。每掷1次骰子（数值1~6），骰子次数 +1。
  - 骰子次数 ≠ 战斗次数（非战斗格也消耗骰子次数）
  - 骰子次数 ≠ 移动格子数（掷1次骰子走1~6格，但骰子次数只+1）
  - 战斗期间不消耗骰子次数
  - 用途：天气变更的驱动计数器（见 §3.1）
```

### 3.5 天气专属命运事件

```
特定天气下，踩到 🎲命运事件格 时，除了从常规事件池抽取外，
还有额外概率触发该天气的专属命运事件。

[触发规则]
  前提条件：当前天气非晴天 且 玩家已解锁天气系统

  踩到命运格时，先判定是否触发天气专属事件：
    Step 1 — 掷骰 [0, 100)，若结果 < (30 + 幸运 × 0.5)% → 触发专属事件
    Step 2 — 触发成功 → 从当前天气专属池抽取事件执行 → 本次命运格结束
              （不再从常规事件池抽取，专属事件完全替代常规事件）
    Step 3 — 触发失败 → 正常从常规事件池按权重抽取（走 [[大地图规则细化案【定案】]] §5 常规流程）

  核心关系：天气专属事件 和 常规事件 是"二选一"的关系。
    踩命运格 → 先掷骰判专属(30%+幸运) → 成则专属/败则常规 → 执行。
    同一命运格不会同时触发专属事件和常规事件。

  叠加重叠检查：
    "好运日"等改变常规池抽取次数的效果 → 仅在走常规池时生效
    专属事件不享受"好运日"的额外抽卡

[反向情况（规则2）]
  - 天气为晴天 → 无专属事件，100%走常规池
  - 天气尚未解锁 → 无专属事件，100%走常规池
```

#### 3.5.1 天气专属命运事件表（仅5个）

| 天气 | 事件名 | 类型 | 效果 | 持续 |
|------|--------|------|------|------|
| ❄️ 暴风雪 | 🏔️ **冬眠** | 特殊 | 所有怪物格不进入战斗，直接按战斗胜利计算全额奖励（金币 + EXP + 装备掉落，与在线战斗胜利完全相同），持续 1 圈 | 1 圈 |
| 🌧️ 细雨 | 🌱 **滋润** | 奖励 | 立即回复 1 枚复活币（不超过上限 3 枚；满币时事件正常消耗，无效果） | 触发即消 |
| 🌫️ 大雾 | 👻 **雾中秘径** | 特殊 | 立即传送到地图上随机 1 个宝箱格并触发该宝箱格 | 触发即消 |
| 🌪️ 沙暴 | 💰 **沙中淘金** | 奖励 | 立即获得 玩家等级 × 200 金币 | 触发即消 |
| 🌌 北极光 | ✨ **许愿** | 奖励 | 立即获得 1 件橙色（传说）品质装备，等级与玩家当前等级匹配 | 触发即消 |

```
每种天气1个专属事件，共5个。触发后等权重随机（每种天气只有1个=100%）。

极端情况（规则3）：
  ├─ 冬眠 + 1圈内没有怪物格 → 无效果（不返还）
  ├─ 冬眠 + 踩到怪物格 → 跳过战斗动画，直接按战斗胜利结算（含金币+EXP+装备）
  ├─ 滋润 + 复活币已满（3/3）→ 事件正常消耗，不返还复活币
  ├─ 雾中秘径 + 地图无宝箱格 → 改为走常规池（专属事件不触发，保底不亏）
  └─ 许愿无失败条件（必定获得1件传说装备）

反向情况（规则2）：
  ├─ 天气变更后专属事件是否失效？
  │   → 不失效。天气专属命运事件的效果一旦触发，持续到标注时间结束，
  │     不受天气变更影响（类似"药效已经吃下去了"）
  ├─ 冬眠期间天气从暴风雪变为其他天气？
  │   → 冬眠效果持续到1圈结束，不受天气变更影响
  └─ 离线期间触发天气专属命运事件？
      → 自动判定并执行，奖励类取最优结果

设计柱检验：
  天气专属命运事件 → 满足柱2（Build深度）+ 柱5（不肝不氪）
  - 冬眠：暴风雪天走圈，跳过战斗直接拿金币，但放弃经验 — 策略取舍
  - 滋润：细雨+1复活币，给玩家额外容错
  - 雾中秘径：大雾中传送宝箱，迷雾中的一线光明
  - 沙中淘金：沙暴中获取金币，风暴中的小确幸
  - 许愿：北极光下获得传说装备，极低概率下的终极惊喜
```

## 4. 战斗中的天气效果（详细）

### 4.1 ⛈️ 雷雨天

```
触发条件：进入战斗后、天气为雷雨天时

每 5 秒 → 1 道闪电随机劈中 1 个目标（不分辨敌我）
  └─ 从"战斗内所有存活单位"中均匀随机选 1 个
  ├─ 被选中的单位 → 立即受到最大 HP × 10% 的绝对伤害
  └─ [强制] 绝对伤害：无视防御/减伤/护盾/闪避/格挡，必须扣除

闪电具体规则：
  - 计时：战斗开局计时 = 0，第 1 道闪电在第 5 秒落下
  - 目标死亡：若闪电目标是已死亡的单位 → 重新随机选 1 个存活单位
  - 全体阵亡：若当前全体单位都死亡 → 闪电不触发，跳过
  - 包括 Boss：Boss 也是合法目标，和普通单位同等概率被劈

视觉表现：
  屏幕上方出现乌云 → 一道闪电从云层劈下 → 击中目标 → 目标颤抖 + 闪电特效
```

#### 4.1.1 闪电概率表（多单位战斗举例）

| 战斗类型 | 参战单位 | 某单位被劈概率 |
|---------|---------|--------------|
| 普通战斗 | 玩家 + 1 小怪 = 2 单位 | 各 50% |
| 精英战斗 | 玩家 + 2~3 怪物 = 3~4 单位 | 各 25%~33% |
| Boss 战斗 | 玩家 + Boss = 2 单位 | 各 50% |
| 挑战格 3 波 | 每波独立概率，按该波存活单位算 | 逐波重置 |

> 规则6（随机明确）：
> - 目标选择 = 均匀随机（等权重）
> - 不放回型：下轮闪电从活着的中选
> - 没有保底，纯运气

### 4.2 🌧️ 细雨

```
持续效果（战斗全程）：
  ├─ 所有单位回复效果 +30%
  └─ 所有单位护盾收益 +30%

适用来源：
  回复效果 = 技能治疗、宝石吸血、套装回血、药品等所有 HP 恢复来源
  护盾收益 = 技能护盾、装备护盾、被动护盾等所有护盾生成来源

叠加规则：
  与烈日对治疗/护盾的减益同时存在时：
  先减益后增益（或反之？需与程序确认叠加算法）
  例：烈日 -40% 治疗 × 细雨 +30% 治疗 → 净效果 = 1 × 0.6 × 1.3 = 0.78（即 -22%）

视觉表现：
  画面笼罩细密雨丝 + 柔光效果 + 水滴在角色周围弹跳
```

### 4.3 🌫️ 大雾

```
持续效果（战斗全程）：
  ├─ 所有单位命中率 × 0.8（降至原来的 80%）
  └─ 所有单位闪避率 × 1.2（升至原来的 120%）

重要：采用乘法修正（见 §2.2），非减法。

  [正确示例]
  命中率 20% → 20% × 0.8 = 16%（而非 20% - 20% = 0% ❌）
  命中率 10% → 10% × 0.8 = 8%（而非 10% - 20% = -10% ❌）
  命中率 100% → 100% × 0.8 = 80%

  不设下限保护：0% × 0.8 还是 0%，乘法修正后即为最终值。

特殊交互：
  - 大雾下，无法触发"精确瞄准"类技能特殊效果（如有）
  - 大雾下，AOE 技能的目标数量不缩减（只影响命中判定）

视觉表现：
  画面笼罩浓雾 + 距离感模糊 + 单位轮廓半透明
```

### 4.4 ❄️ 暴风雪

```
持续效果（战斗全程）：
  └─ 每 8 秒随机冻结 1 个目标，持续 2 秒

冻结目标选择（规则6 随机明确）：
  - 从"战斗内所有存活单位"中按权重随机选择 1 个
  - 权重 = 1 / 该单位的实际出手CD
  - 出手CD越短 → 权重越高 → 越容易被冻结

  权重计算：
    每个存活单位的权重 W_i = 1 / 实际出手CD_i
    总权重 W_total = Σ W_i
    单位 i 被冻结概率 = W_i / W_total

  示例（3 单位战斗）：
    ├─ 玩家出手CD 2.0s → 权重 0.500
    ├─ 小怪A 出手CD 3.0s → 权重 0.333
    └─ 小怪B 出手CD 4.0s → 权重 0.250
    总权重 = 1.083
    玩家被冻结概率 = 0.500 / 1.083 ≈ 46.2%
    小怪A被冻结概率 = 0.333 / 1.083 ≈ 30.7%
    小怪B被冻结概率 = 0.250 / 1.083 ≈ 23.1%

  设计意图：
    速度快的单位行动更频繁 → 身体暴露在暴风雪中更多 → 更容易被冻结
    这是对"全堆速度"Build的自然反制——攻速流在暴风雪中会频繁被冻结

冻结效果（引用 [[技能系统细化案【定案】]] §4.1 冻结定义）：
  ├─ 被冻结单位无法行动（无法普攻/放技能）
  ├─ 被冻结期间受击伤害 +50%（破冰加伤）
  ├─ 冻结自然结束时立即移除冻结状态（不叠加后续效果）
  └─ 对 Boss：冻结持续时间减半（2秒→1秒）

冻结定时规则：
  ├─ 计时：战斗开局计时 = 0，第 1 次冻结在第 8 秒触发
  ├─ 每 8 秒触发 1 次，重新按权重随机选目标
  ├─ 同一单位可被连续冻结（第 1 次冻结结束后，下次仍可能选中它）
  └─ 已处于冻结状态的单位仍参与权重计算（可被"续冻"）

极端情况（规则3）：
  ├─ 仅 1 个存活单位 → 100% 被冻结
  ├─ 所有单位出手CD相同 → 均匀随机（各 1/N）
  ├─ 出手CD = 0（理论上不可能，速度上限50%=1.5s）→ 权重极高
  └─ 全体阵亡 → 冻结不触发

反向情况（规则2）：
  ├─ 目标已处于冻结状态 → 刷新冻结持续时间为 2 秒（Boss 1 秒）
  ├─ 冻结期间单位死亡 → 冻结自然消失，不影响后续冻结选择
  └─ 暴风雪天气结束时已有冻结 → 冻结正常持续到时间结束，不会提前解除

视觉表现：
  画面飘雪 + 雪花粒子 + 被冻结单位覆盖冰晶外壳 + 蓝白色结霜特效
  冻结触发时：冰柱从地面升起包裹目标 + 冰碎裂音效
```

## 6. 战斗初始化中的天气集成

### 6.1 天气注入战斗流程

```
[地图掷骰时 — 天气变更检查]

Step 0 — 玩家在大地图掷骰移动，骰子计数器 +1
Step 1 — 检查骰子计数器是否 ≥ 阈值 T
  └─ 是 → 触发天气变更（见 §3.1），重置计数器和阈值
  └─ 否 → 无事发生
Step 2 — 角色按骰子点数移动，触发踩到的格子事件

[每次战斗开始时 — 天气效果注入]

Step 1 — 获取当前玩家的个人天气
Step 2 — 根据天气类型初始化战斗场景（背景/粒子/光照）
Step 3 — 应用固定属性修正（乘法修正：大雾命中率×0.8、暴风雪冻结机制等）
Step 4 — 注册周期性效果定时器（雷雨天闪电、暴风雪冻结、沙暴风沙等）
Step 5 — 战斗 UI 右上角显示当前天气图标 + 名称
Step 6 — 战斗正式开始

[战斗结束后]

Step 7 — 注销所有天气定时器
Step 8 — 释放天气粒子/视觉效果资源
Step 9 — 检查骰子计数器是否 ≥ 阈值 T
  └─ 是 → 触发天气变更（见 §3.1），重置计数器和阈值
  └─ 否 → 无事发生
```

### 6.2 天气与离线处理（规则3 极限情况）

离线期间不走格，因此不增加骰子次数、不轮换天气、不触发天气战斗效果或天气专属命运事件。上线后恢复离线前的当前天气、计数器和阈值；离线金币与经验按 [[战斗系统规则案【定案】]] §11 的统一10%效率公式结算，天气不参与离线收益修正。

反向情况：上线后的第一次掷骰正常使计数器+1；如果因此达到阈值，则在该次掷骰后正常变更天气。

## 附录 A：个人天气的确定性种子算法

```
为确保离线期间天气推算的确定性，每个玩家的天气序列由种子决定：

[生成规则]
  1. 玩家解锁天气时，基于 玩家ID × 解锁时间戳_unix 计算种子 seed
  2. 使用轻量伪随机算法（如 xorshift32）从种子生成后续天气序列
  3. 天气序列预生成 N 次（N= 96 次），存入玩家数据
  4. 天气变更由掷骰次数触发，而非时间，因此序列索引按"已变更次数"推进
  5. 玩家每次上线时，根据当前序列索引读取当前天气及未来 N 次预报
  6. 离线时：通过种子 + 当前变更次数推算，无需额外存储

[存储方案]
  ├─ 玩家表字段：weather_seed (int64) + weather_sequence_index (smallint)
  ├─ weather_sequence_index = 已发生的天气变更次数
  └─ 每次天气变更 → index + 1，从预生成序列中取下一项
      超出 96 则重新批量预生成下一段

[特点]
  - 序列用于"确定第 N 次变更为哪个天气"
  - 实际是否触发变更取决于骰子计数器（战斗中是否累计到阈值）
  - 天气预报 = 从序列中读取当前 index+1 的天气（前提是下次变更会触发）
  - 玩家A和B的天气永远不会"互相影响"
```
