# 拍卖行系统细化案 v0.3

> 对应：GDD §16 拍卖行系统 + §17 经济平衡（拍卖相关）
> 版本：v0.3 | 日期：2026-05-25 | 状态：待 ybf 确认
> v0.2→v0.3 变更：① 删除邮件系统，新增 §2 拍卖行背包（30格，系统自动放入，玩家可取非上架物品，一键取回）；② 上架上限 10→3 件；③ 上架物品标记"上架中"并锁定在拍卖行背包中；④ 成交/流拍/取消全部改为走拍卖行背包

---

## 1. 设计柱检验

系统级别的设计柱校验：

> **柱6（玩家经济）**：拍卖行是玩家经济的核心枢纽，让玩家淘汰的装备变成可交易的「资产」，形成装备流通→金币流通→系统回收的闭环。
>
> **柱2（Build深度）**：拍卖行让玩家可以定向收购套装部件和词条好的橙装，加速Build成型，提升搭配自由度。
>
> **柱5（不肝不氪）**：通过交易获取装备替代反复刷图，减少重复劳动。策略在「判断装备价值」而非「肝掉落」。

## 2. 拍卖行背包

```
独立于装备背包的 30 格专用存储空间，仅用于存放拍卖行相关的物品。
玩家不可手动将物品放入，但可取走非拍卖中的物品。
```

| 规则 | 内容 |
|------|------|
| 容量 | 30 格（不可扩容） |
| 谁放入 | 系统自动——上架物品、竞拍成功获得的物品 |
| 谁取出 | 玩家手动——仅限非"上架中"状态的物品 |
| 一键取回 | 支持，一键将所有非上架中物品移入装备背包 |
| 手动放入 | 不支持——玩家不能从装备背包拖物品进来 |
| 拍卖行背包满 | 无法上架新物品，提示"拍卖行背包已满（30/30），请清理后重试" |
| 剩余容量 < 3 | 无法上架物品，也无法从拍卖行购买。飘字提示"拍卖背包快满了，清理一下吧" |

```
物品状态说明：
  ├─ "上架中" → 正在拍卖行出售，锁定在拍卖行背包中，不可取出。计入容量占用
  ├─ "竞拍获得" → 竞拍成功获得的物品，暂存在拍卖行背包，可取出或一键取回。计入容量占用
  ├─ "流拍退回" → 上架后无人出价退回的物品，暂存在拍卖行背包，可取出。计入容量占用
  └─ "取消下架" → 卖家主动取消的拍卖物品，回到拍卖行背包。计入容量占用

容量门槛规则：
  剩余容量 = 30 - 当前已占用格数
  剩余容量 ≤ 2 → 上架按钮灰掉 + 竞拍按钮灰掉，飘字"拍卖背包快满了，清理一下吧"
  剩余容量 ≥ 3 → 正常上架和竞拍

拍卖行背包与装备背包的关系：
  装备背包 ← 一键取回/手动取出 ← 拍卖行背包
  装备背包 → 上架 → 拍卖行背包（标记"上架中"）
  
  买家竞拍成功 → 物品进入买家拍卖行背包（标记"竞拍获得"）
  流拍/取消 → 物品保留在卖家拍卖行背包，解除"上架中"标记
```

## 3. 可上架物品范围

### 3.1 核心规则

> 只有满足以下**任一**条件的物品可以上架拍卖行：
>
> 1. **套装装备** — 身上带有任意套装词条的装备（不限品质，从普通到传说均可）
> 2. **传说（橙）品质装备** — 品质=传说（不论是否带有套装词条）
> 3. **宝石** — 全部 8 种宝石（Lv.1~Lv.10 均可）
> 4. **打孔器** — 给装备增加插孔的稀有消耗品
>
> 以下物品**不可**上架：
> - 非套装 + 非传说品质的装备（普通/精良/稀有/史诗 × 无套装）
> - 天命卡、合成券、强化碎片等消耗品/货币
> - 已装备在角色身上的装备
> - 已处于上架状态的物品（同一件不可重复上架）
> - 锁定状态的装备（见 §8）

#### 2.1.1 可上架判定流程

```
[玩家点击"拍卖"按钮时]
Step 1 — 检查该装备是否已装备？
  ├─ 是 → 拒绝，提示："请先卸下装备"
  └─ 否 → 进入 Step 2
Step 2 — 检查该装备是否已上架？
  ├─ 是 → 拒绝，提示："该装备已在拍卖行中"
  └─ 否 → 进入 Step 3
Step 3 — 检查是否满足"可上架条件"？
  ├─ 是（套装装备 或 传说品质 或 宝石 或 打孔器）→ 进入上架流程（§3）
  └─ 否 → 拒绝，提示："只有套装装备、传说品质装备、宝石或打孔器可以拍卖"
     拒绝后操作：
       └─ 弹出"分解建议"按钮 → 点击跳转分解界面
```

#### 2.1.2 为何限制（装备）

| 原因 | 说明 |
|------|------|
| 价值锚定 | 套装和橙色是装备价值的核心锚点，玩家一眼能判断"这件值得卖" |
| 背包负担 | 如果垃圾装备也能拍卖，背包里每件装备都要评估→背包爆炸 |
| 经济控制 | 限制装备供给量防止拍卖行被低价值装备淹没，保持高品质装备的稀缺感 |
| 定性 | 套装=凑Build用，橙装=顶级属性，两者都有明确买家群体 |

> 宝石和打孔器是例外：宝石有明确的等级价值体系，玩家可按等级定价；打孔器是顶尖稀有物，天然高价值。两者均不会被低价值物品淹没拍卖行。

> 设计柱检验：限制拍卖范围保证「拍卖行=精品市场」而非"装备垃圾桶"，符合柱5（不肝不氪）的"决策在搭配不在刷量"原则。

### 3.2 物品绑定规则

```
拍卖行中所有物品的绑定状态决定其是否可交易。
```

| 物品类型 | 绑定规则 | 来源 |
|---------|---------|------|
| 装备 | **无绑定机制**——装过后卸下即可交易。掉落后自由交易，强化/镶嵌/拆卸宝石不影响交易状态。已锁定装备需手动解锁后才可交易。 | [[装备系统细化案【定案】]] §10.2 |
| 宝石 | **无绑定机制**——所有宝石自由交易。镶嵌后拆卸不绑定，可随时上架拍卖行。 | [[装备系统细化案【定案】]] §7 |
| 打孔器 | **无绑定机制**——获得即可交易。 | — |

```
设计意图：
  - 挂机游戏核心是"刷→配→换"，频繁更换装备是常态
  - 无绑定 = 闲置装备和宝石可以回流市场 → 支撑拍卖行供给
  - 经济风险通过上架费(1%)和成交手续费(5%)回收，不靠绑定限制流通
```

### 3.3 宝石交易细则

```
宝石是拍卖行的可交易物品（与装备并列）。

可交易宝石类型：
  全部 8 种宝石（红/蓝/绿/黄/紫/钻/橙/银）
  等级 Lv.1 ~ Lv.10，不限等级

上架规则：
  宝石上架流程与装备相同（见 §3）
  上架费 = 系统估价 × 1%（下限 100 金 / 上限 5,000 金）
  成交手续费 = 成交价 × 5%

估价算法（框架，[待定]）：
  宝石估价 = 基础价 × 2^(等级-1)
  基础价：[待定]（红/蓝/绿各不同，黄/紫/钻/橙/银更高）
```

> 宝石生成/合成规则见 [[装备系统细化案【定案】]] §7

## 4. 上架流程

### 3.1 操作流程

```
[满足上架条件后]

Step 1 — 系统估价
  系统根据装备等级、品质、词条数、强化等级、套装稀有度等信息
  生成一个"建议估价"作为基准（算法见 §3.3）

Step 2 — 玩家设定参数
  ┌─ 起拍价：玩家手动输入，下限=估价×30%，上限=无限制
  ├─ 一口价（可选）：≥起拍价，设定后买家可直接以该价格秒杀
  └─ 拍卖时长：8小时 / 12小时 / 24小时（下拉选择）

Step 3 — 确认上架费
  上架费 = 估价 × 1%（向下取整）
  下限：100金币
  上限：5000金币
  例：估价=30万金 → 上架费=3000金
  例：估价=5000金 → 上架费=100金（下限兜底）

Step 4 — 支付上架费
  ├─ 同时上架数量已达上限（3 件）→ 拒绝，提示"您已上架 3 件物品，请等待现有拍卖结束后再上架"
  ├─ 玩家金币 ≥ 上架费 → 扣除金币，装备从装备背包移出，进入拍卖行背包（标记"上架中"，锁定不可取出）
  └─ 玩家金币 < 上架费 → 拒绝，提示金币不足

Step 5 — 上架成功
  装备进入拍卖队列，其他玩家可在搜索中看到该装备
  上架者收到系统消息："您的装备【武器名】已上架，拍卖编号：XXXX"
```

### 3.2 上架失败场景

| 失败原因 | 提示 | 处理 |
|---------|------|------|
| 金币不足支付上架费 | "金币不足，无法支付上架费" | 界面保留玩家已填参数，不丢失 |
| 拍卖行背包已满 | "拍卖行背包已满（30/30），请清理后重试" | 流拍处理见 §6 |
| 网络中断导致上架中断 | "上架失败，请重试" | 装备安全（扣费未成功，装备仍在背包）|
| 服务器重启中 | "系统维护中，请稍后再试" | 维护期间拍卖行不可用 |

### 3.3 估价算法框架

> 估价算法的精确数值 `[待定]`，框架结构如下：

```
估价 = 基础价值 × 品质系数 × 套装修正 × 强化修正 × 等级修正

基础价值：1000 金币（固定底价）
品质系数：普通=1.0 / 精良=1.2 / 稀有=1.5 / 史诗=2.5 / 传说=5.0
套装修正：无套装=1.0 / 有套装=×1.8
强化修正：1 + 强化等级 × 0.1
等级修正：1 + (装备等级 - 1) × 0.02
```

> 例：Lv.30 传说品质 + 套装 + 强化+10
> → 1000 × 5.0 × 1.8 × (1 + 10×0.1) × (1 + 29×0.02) = 1000 × 5.0 × 1.8 × 2.0 × 1.58 ≈ **28,440 金**

> 设计意图：估价是系统建议值，玩家可以自行设定高于估价的起拍价。估价不限定成交价上限，只作为计算上架费和起拍价下限的基础。

| 剩余时间 | 即将结束 / 全部 | 快速筛选 |

### 4.2 排序方式

| 排序 | 默认降序 | 说明 |
|------|---------|------|
| 最近上架 | 新→旧 | 默认排序 |
| 价格 | 高→低 / 低→高 | 按当前最高出价排序 |
| 等级 | 高→低 / 低→高 | 装备等级 |
| 剩余时间 | 短→长 | 即将结束排列靠前 |

### 4.3 搜索性能约束

```
每次搜索最多返回 200 条结果（分页显示，每页20条）
重新搜索冷却：3秒
搜索索引更新延迟：上架/成交后最长 5 秒（非实时，异步索引）
```

> 规则3（极限情况）：
> - 无搜索结果 → 显示"未找到符合条件的装备" + 推荐清空筛选条件
> - 搜索条件过多组合 → 系统自动移除最不具体的条件并提示
> - 同时在线搜索峰值 → 每3秒冷却限制 + 页面缓存，避免数据库过载

## 6. 竞拍规则

### 5.1 出价流程

```
[买家找到心仪装备]

Step 1 — 查看装备详情（品质/词条/强化/套装等信息）
Step 2 — 查看当前最高出价
Step 3 — 输入出价金额
Step 4 — 出价校验：
  ├─ 出价 ≥ 当前最高价 + 最低加价幅度（见§5.2）→ 出价成功
  └─ 出价 < 该要求 → 提示："出价需至少达到 XXX 金币"
Step 5 — 扣款与锁定：
  ├─ 买家金币 ≥ 出价额 → 立即扣除出价额（锁定）
  └─ 买家金币 < 出价额 → 提示："金币不足"
Step 6 — 出价成功：
  ├─ 更新当前最高出价
  ├─ 向前一位最高出价者退还其被超出的出价金
  └─ 通知原最高出价者"您已被超过"
```

#### 5.1.1 金币锁定规则

```
出价成功后，出价金币立即从买家背包余额中扣除，进入系统托管账户（冻结状态）。
冻结期间该金币不计入买家可用余额，买家无法使用。

冻结金币的生命周期：

[出价]
  买家出价成功 → 金币从买家背包 → 系统托管账户（冻结）
  买家看到提示："已出价 XXX 金币（已冻结）"

[被超过]
  有更高出价 → 系统立即从托管账户解冻 → 退还买家背包
  买家看到提示："您的出价已被超过，XXX 金币已退还"

[成交 — 成为最高出价者且拍卖结束]
  Step 1 — 系统从托管账户中扣除成交手续费
  Step 2 — 剩余金币从托管账户 → 卖家背包（卖家离线则直接到账）
  Step 3 — 托管账户中的冻结记录销毁
  
  卖家看到："您的【装备名】以 XXX 金币成交，到账 YYY 金币（已扣手续费）"
  买家看到："恭喜竞拍成功，成交价 XXX 金币"

[流拍 — 无人出价]
  无冻结金币，无需处理

[取消/下架]
  所有出价者的冻结金币立即解冻 → 退还各自背包
  系统通知："拍卖已取消，冻结金币已退还"

关键保证：
  ├─ 托管账户是系统中间账户，玩家不可直接操作
  ├─ 冻结期间的金币所有权仍属买家（只是不可使用）
  ├─ 任何非成交结局 → 冻结金币必定全额退还
  └─ 成交时 → 手续费从托管账户扣除后才转给卖家，卖家不接触手续费
```

### 5.2 最低加价幅度（阶梯）

| 当前最高价范围 | 最低加价幅度 |
|---------------|------------|
| 0 ~ 10,000 金 | +500 金 |
| 10,001 ~ 50,000 金 | +1,000 金 |
| 50,001 ~ 200,000 金 | +2,500 金 |
| 200,001 ~ 500,000 金 | +5,000 金 |
| 500,001 金以上 | +10,000 金 |

> **设计意图**：阶梯加价防止低价值装备被1金币站桩顶价，也让高价值竞拍保持合理烈度。

### 5.3 代理出价（自动加价）

```
买家可以设置一个"最高心理价"（代理出价）。

系统自动代理规则：
  1. 买家输入最高价 → 系统自动以最低加价幅度递增出价
  2. 当有其他人出价时 → 系统在1秒内自动加价（不超过设定的最高价）
  3. 当系统已达到买家的最高价 → 停止自动加价，转为普通最高出价
  4. 买家本人看到的界面提示：当前被代理状态 / 已达上限

代理出价与手动出价的关系：
  - 代理出价优先级 = 普通出价（两者平等，谁价高谁赢）
  - 多人同时代理同一件装备 → 按最高代理价排序，相同则先设定者优先

例：
  A 设置代理最高价 50,000 金，当前价 10,000 金
  B 手动出价 15,000 金
  → 系统自动将 A 的代理出价提到 15,500 金（最低加价）
  → B 再手动出价 20,000 金
  → 系统将 A 提到 20,500 金
  ... 直到 A 达到 50,000 金上限或对方放弃
```

### 5.4 一口价规则

```
若卖家设定了"一口价"：
  - 买家可以直接以一口价购买 → 立即成交
  - 一口价条件下跳过竞拍流程
  - 一口价成交后，所有代理出价自动取消，冻结金币退还

一口价不可用场景：
  - 已有代理出价的装备 → 一口价仍然可用，直接结束竞拍
  - 一口价 ≥ 当前最高价的 200% → 系统建议卖家调整（不强制）

设计意图：一口价=急买/急卖渠道，方便急需金币的卖家快速变现。
```

### 5.5 出价失败与退回

| 场景 | 处理 |
|------|------|
| 出价被超过 | 原出价金额立即解冻，退回背包（可继续出价其他装备） |
| 装备被一口价买走 | 所有其他出价者冻结金币立即退回 |
| 装备下架/取消 | 所有出价者冻结金币立即退回 |
| 服务器回档 | 拍卖行状态回档到快照点，重新开放 |

## 7. 成交与流拍

### 6.1 成交

```
[倒计时归零 → 无人出价 → 结束]

成交触发流程：
  Step 1 — 锁定当前最高出价者
  Step 2 — 扣除成交手续费（见 §7）
  Step 3 — 装备转移：从拍卖行库 → 买家拍卖行背包（标记"竞拍获得"）
  Step 4 — 金币转移：已锁定的出价金 → 卖家背包（扣除手续费后）
  Step 5 — 通知双方：
    ├─ 买家："恭喜，您成功拍得【装备名】，已放入您的背包"
    └─ 卖家："您的装备【装备名】已以 XXX 金币成交，扣除手续费后到账 YYY 金币"
  Step 6 — 更新拍卖行记录
```

### 6.2 成交后处理

```
买家竞拍成功后 → 装备进入买家拍卖行背包（标记"竞拍获得"），可一键取回或手动取出
卖家已离线 → 金币直接到账（离线累积）
```
> 规则3（极限情况）：
> - 买家拍卖行背包已满（30/30）→ 系统提示"拍卖行背包已满，请清理后领取"，物品保留在系统暂存
> - 卖家30天未上线 → 金币正常到账，无过期

### 6.3 流拍

```
[倒计时归零 → 无人出价 → 流拍]

流拍处理：
  Step 1 — 装备退回卖家拍卖行背包，解除"上架中"标记
  Step 2 — 上架费不退还（作为流拍成本）

流拍后推荐操作（界面提示）：
  └─ "建议降价重新上架" → 点击后自动设为原起拍价的 80%
  └─ "一键取回" → 装备移入装备背包
  └─ "转为分解" → 点击跳转分解界面
```

#### 6.3.1 流拍后拍卖行背包满

```
若流拍时卖家拍卖行背包已满（30/30）：
  → 允许暂超出1件（变为31/30）
  → 下次上架或竞拍前必须先清理至30以内
  → 系统提示"拍卖行背包已满，请清理后继续"
```

> 规则3（极限情况）：拍卖行内装备总量无硬性限制（表存储），但每位玩家同时最多上架 3 件物品。上限达到时 → 提示"您已达到同时上架上限（3件），请等待现有拍卖结束后再上架"。

### 6.4 取消上架

```
卖家可以在上架后自行取消拍卖（有限制）：

取消条件：
  ├─ 拍卖开始后 24 小时内可取消
  └─ 已有出价 → 不可取消（防止恶意抬价后撤单）
     ├─ 无出价 → 可取消
     └─ 无出价但剩余时间 < 1小时 → 不可取消（避免最后时刻大量撤单）

取消操作：
  无出价 → 免费取消 → 装备退回拍卖行背包，解除"上架中"标记
  已有出价 → 按钮灰掉 → 提示："已有买家出价，无法取消"
  （违规大量撤单 → 系统标记，连续3次取消后冷却24小时不可上架）
```

## 8. 经济系统

### 7.1 费用总表

| 费用类型 | 费率 | 下限 | 上限 | 用途 |
|---------|------|------|------|------|
| 上架费 | 估价×1% | 100金 | 5,000金 | 防占坑，金币水槽 |
| 成交手续费 | 成交价×5% | 无 | 无 | 系统回收金币 |
| 流拍 | 上架费已扣除 | — | — | 无额外费用 |
| 取消上架（无出价） | 免费 | — | — | 操作友好 |

### 7.2 钱包与到账

```
卖家实际到账 = 成交价 × (1 - 5%) - 已支付的 1% 上架费

例：成交价 50,000 金
  上架费：500 金（先付）
  手续费：50,000 × 5% = 2,500 金（成交后扣除）
  卖家实际到账：50,000 - 2,500 = 47,500 金
  （上架费已先付，不重复退）

若流拍：
  卖家损失：上架费（500金）
```

> 设计意图：上架费+手续费的双重回收是后期游戏最大的金币水槽。上架费防刷，手续费回收流通金币。结合 §17 经济表（人均日收入20~50万金），一个活跃玩家如果每天买卖几件装备，被回收的金币约占日收入的 10%~20%。

## 9. 锁定与安全

### 8.1 装备状态管理

```
装备上架后 → 进入"拍卖中"状态：
  - 不可装备、不可强化、不可合成、不可镶嵌宝石、不可分解
  - 拍卖结束后（成交/流拍/取消）→ 解除锁定

锁定由服务端强制管理，避免前端篡改。
```

### 8.2 防欺诈设计

| 风险 | 防御措施 |
|------|---------|
| 恶意起拍价极低 | 下限 = 估价×30%，低于此值提示确认 |
| 恶意同行抬价 | 代理出价记录 + 同一IP/账号异常出价检测（连续取消≥3次=冷却24h）|
| 盗号转移装备 | 拍卖需要二级密码验证（设置后不可关闭）|
| 恶意刷大量拍卖 | 同时上架上限3件 |

### 8.3 交易记录

```
所有成交记录保留 30 天，供双方查阅：
  - 买家可查：已拍得装备的成交价和时间
  - 卖家可查：已售出装备的成交价、买家匿名ID和时间
  - 系统后台可查：完整记录（防申诉）
```

## 11. 性能与存储

### 10.1 数据结构（概要）

```
拍卖行表 auction_listings：
  ┌─ id (BIGINT PK)          # 拍卖编号
  ├─ seller_id (INT)          # 卖家玩家ID
  ├─ equipment_id (BIGINT)    # 装备实例ID
  ├─ starting_price (INT)     # 起拍价
  ├─ buyout_price (INT?)      # 一口价（可为NULL）
  ├─ current_bid (INT)        # 当前最高出价
  ├─ current_bidder_id (INT?) # 当前最高出价者
  ├─ estimated_value (INT)    # 系统估价
  ├─ listing_fee (INT)        # 已支付上架费
  ├─ status (ENUM)            # active / sold / expired / cancelled
  ├─ created_at (DATETIME)    # 上架时间
  ├─ expires_at (DATETIME)    # 过期时间
  ├─ extend_count (TINYINT)   # 已延长次数
  └─ bid_count (INT)          # 出价次数

出价表 bid_records：
  ┌─ id (BIGINT PK)
  ├─ listing_id (BIGINT)
  ├─ bidder_id (INT)
  ├─ amount (INT)
  ├─ is_auto (BOOLEAN)        # 是否为代理出价
  ├─ created_at (DATETIME)
  └─ ... (索引：listing_id + amount DESC)
```

### 10.2 性能约束

| 操作 | 限制 | 说明 |
|------|------|------|
| 频繁搜索 | 3秒冷却，缓存化 | 搜索走 Redis 缓存，不直接查 MySQL |
| 出价操作 | 实时写入 | 出价涉及余额锁定，必须实时 |
| 倒计时更新 | 每30秒批量更新轮询 | 或委托给定时任务 |
| 历史数据 | 成交记录保留30天，可归档 | 30天前数据压缩存储 |
| 并发出价 | 行级锁 + 乐观锁 | 同一装备的并发出价用版本号控制 |

> 规则4（性能负载）：
> - 搜索结果实时性要求不高（5秒延迟可接受）→ 只需对"即将结束"的物品做实时索引
> - 出价必须实时 → 写入操作直接用乐观锁避免冲突
> - 全服活跃玩家按1000人估算 → 同时活跃拍卖物品约1000~3000件 → 常规数据库可承载

## 12. 设计柱检验（汇总）

| 设计决策 | 对应柱 | 检验 |
|---------|-------|------|
| 仅套装/橙装可拍卖 | **柱2** Build深度 | 定向凑套装/淘极品橙色→增加Build自由度 |
| 仅套装/橙装可拍卖 | **柱5** 不肝不氪 | 减少"每件垃圾都要评估"的决策疲劳 |
| 上架费+成交手续费 | **柱6** 玩家经济 | 双重金币水槽，维持金币长期价值 |
| 防狙击延长机制 | **柱6** 玩家经济 | 公平竞拍→玩家信任→经济活跃 |
| 代理出价 | **柱5** 不肝不氪 | 降低盯盘压力，挂机友好 |
| 流拍后系统回收补偿 | **柱6** 玩家经济 | 避免无限滞留未领取物品，保持流通性 |
| 同时上架上限3件 | **柱6** 玩家经济 | 防止大户垄断市场，普通玩家也有机会成交 |
| 宝石/打孔器可拍卖（v0.2） | **柱6** 玩家经济 | 宝石为有限资源，拍卖提供二级流通市场；打孔器稀有掉落拉动经济 |
| 装备无绑定（v0.2） | **柱6** 玩家经济 | 装备可反复流通，每次交易产生手续费回收金币 |
