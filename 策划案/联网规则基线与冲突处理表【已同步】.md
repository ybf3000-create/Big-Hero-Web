## 1. 已确认产品基线

| 范围 | 已确认规则 |
|------|-----------|
| 联机人数 | 最多 20 个账号同时在线；第 21 人提示“服务器人数已满，请稍后登录”，不排队、不踢其他玩家 |
| 同账号登录 | 新设备登录成功并踢下旧设备；同账号最多 1 个可写会话 |
| 断线重连 | 保留在线名额 30 秒，超时释放名额并进入离线状态 |
| 注册 | 邀请码自动注册；邀请码有效则直接通过，不需要管理员逐个审批 |
|验证与找回 | 不收集邮箱和手机号，不用短信/邮件验证；忘记密码由玩家私下联系管理员重置临时密码 |
| 角色 | 每账号 1 个角色；角色名全服唯一 |
| 角色名长度 | 仅允许汉字、英文字母和数字；汉字计 2，字母/数字计 1，总计 1~14；即最多 7 个汉字或 14 个字母/数字 |
| 部署 | 一台 Windows 自有电脑作为服务器；需新建数据库和备份流程 |
| 公网入口 | 使用内网穿透；没有自有域名，使用穿透服务提供的稳定 HTTPS/WSS 地址或后续配置域名 |
| 客户端 | 保留 Godot 4 并导出 Web；首版支持桌面 Chrome、Edge |
| 世界关系 | 每人独立地图和挂机进度，只共享世界聊天与拍卖行 |
| 本地存档 | 不迁移，联网服全部从新角色开始 |
| 离线收益 | 服务端按公式一次性结算，最多累计 12 小时；离线不逐格、不逐场模拟 |
| 彩票 | 每个角色个人开奖；号码范围 000~999，共 1,000 个等概率结果 |
| 聊天 | 只有世界频道和只读系统频道；世界消息保存 7 天；无私聊、交易频道、拍卖分享和举报 |
| 聊天治理 | 玩家可屏蔽；管理员可按小时禁言，最长 72 小时；首版不做敏感词过滤 |
| 拍卖 | 仅一口价；可卖套装装备、传说装备、宝石、打孔器；有宝石的装备必须先拆下宝石 |
| 交易绑定 | 从拍卖行买到的物品永久绑定该买家角色，不可再次上架；玩家自己掉落且未成交过的合格物品可上架 |
| 拍卖容量 | 同时最多上架 3 单，拍卖仓库 30 格，上架时长 8/12/24 小时 |
| 市场托底 | 不生成系统订单，不做系统收购或出售 |
| 管理工具 | 邀请码管理、重置临时密码、删号、按小时禁言、按小时封号；禁言和封号最长 72 小时 |
| 管理限制 | 不做管理员发金币或装备；账号注册不需要审批 |
| 规则优先级 | 数值以 [[数值设计总表]] v3.6 为第一基线，玩法以各【定案】细案为基线，再按本表覆盖明确冲突 |
| 设计柱 | 恢复柱6“玩家经济” |

### 1.1 本次统一确认

| 项目 | 统一规则 |
|------|---------|
| Boss与档位上限 | Boss#、怪物档位均为 1~200；Boss21~200不再扩张地图，只继续提升档位难度；数值细节以 [[数值设计总表]] §3 为准 |
| 规则执行位置 | 服务器执行原版 Godot 规则并生成掷骰、战斗、装备、掉落、金币、经验、彩票等价值结果；客户端只能发送操作意图和展示结果 |
| 自由防御 | 每点 -1.2% 受伤，上限50%，与装备防御减伤乘算 |
| 宝石 | 共8种，包含银宝石；普通随机宝石池按8种均匀抽取 |

### 1.1 拍卖费用定案

拍卖价格由卖家自行填写，不做系统估价。创建订单免费；仅在成交成功后收取 `floor(成交价 × 5 / 100)` 金币手续费；交易失败不收费。成交价为 1~19 金币时，手续费因向下取整为 0。

> 设计柱检验：个人地图不被联网改造成同步玩法，保留柱1与柱4；世界聊天和受控拍卖恢复柱6；无审批、无私聊、无系统托底保持熟人小服的低负担，符合柱5。

## 3. 同步顺序

```text
Step 1 Q32确认免费创建订单与5%成交手续费（已完成）
Step 2 按 C01~C16 修订总纲、定案案、开发计划和数值引用（已完成）
Step 3 每份被改文档升版本并追加变更记录（已完成）
Step 4 对照本表逐条检查，不允许同一规则残留两个有效值（已完成）
Step 5 建立 `rules_version`，客户端和服务端共同引用（进入开发）
```

同步失败时，不删除旧段落后假定新规则生效；应在冲突表保留“未同步”状态，并禁止依赖该规则的代码进入联网主分支。

## 4. 性能、随机与容量影响

| 规则 | 影响 |
|------|------|
| 20 人在线、单角色 | 活跃角色上限20，角色列表无需分页，服务端仍按账号归属校验 |
| 30 秒断线保留 | 在线名额管理器每10秒批量清理一次超时会话，不为每个会话建立独立线程 |
| 个人彩票000~999 | 服务端从 `[0,999]` 均匀抽取整数并补足3位；单票中奖率固定0.1% |
| 离线12小时公式 | 登录时批量结算一次，不逐秒、逐格或逐场循环 |
| 拍卖3单×20角色 | 全服最多60个有效上架订单；数据库索引和分页足够，不引入Redis |
| 交易后绑定 | 成交只改变一次物品所有权与绑定状态，不产生新物品 |

随机失败分支：服务端随机源不可用或规则版本缺失时，彩票、掷骰、装备掉落等价值操作整体失败并回滚，客户端不得补随机结果。

## 5. 设计柱检验

| 处理 | 设计柱 | 检验 |
|------|--------|------|
| 恢复玩家经济但只做一口价 | 柱2、柱6 | 支持定向Build，同时降低竞价复杂度和盯盘负担 |
| 成交后永久绑定 | 柱3、柱6 | 抑制倒卖并保留Boss掉落价值，但会降低二次流通 |
| 个人地图、个人彩票、公式离线 | 柱1、柱4、柱5 | 联网不改变个人挂机核心，也不强迫同步在线 |
| 统一数值基线 | 柱2、柱5 | 避免玩家看到的属性、冷却和养成目标互相冲突 |

⚠ 设计柱冲突：交易后永久绑定会削弱柱6的重复流通，但这是 ybf 明确选择，用于限制倒卖；拍卖仍可完成首次掉落到需求玩家的流通。
