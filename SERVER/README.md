# 大勇者服务端 v0.9

本目录是Godot浏览器网络版的单体服务，也是唯一维护的服务端。当前代码覆盖邀请码注册、账号密码登录、安全记住登录、最多20个账号同时在线、同账号新端踢旧端、30秒断线恢复、每账号1个角色、玩家输入角色名确认删除角色、世界聊天和一口价拍卖行。地图、Boss 1～200、装备、宝石、技能、属性点、掉落、扑克奖励、天命卡及离线收益已改为服务端运算并接回Godot网页界面。游戏命令在SQLite事务提交后才返回；客户端响应丢失或战斗中断线时，重新同步状态仍会得到已结算的奖励，request_id重试不会重复结算。自动测试和本机浏览器流程已通过，但另一台物理电脑的ZeroTier跨机完整玩法仍需最终验收。桌面原生客户端不再交付或维护。

## 1. 运行条件

| 软件 | 要求 | 当前开发机 |
|------|------|-----------|
| Node.js | 22或更高 | 已安装24.13.1 |
| SQLite | 由服务端内置，无需单独安装 | 已完成真实数据库验收 |
| 浏览器 | Chrome或Edge | 访问服务器网页即可 |

SQLite只允许单个游戏服务进程读写。运行库使用WAL、外键、5秒写锁等待和强同步；ZeroTier网络只暴露游戏HTTP端口，不提供数据库访问入口。ZeroTier负责网络连通和加密，浏览器不需要额外证书或命令。

## 2. 首次启动

```powershell
cd D:\onedrive\note\Game\Game-大勇者\SERVER
Copy-Item .env.example .env
npm ci --include=dev --ignore-scripts
npm run migrate
npm run invite:create -- --count=5
```

无需安装数据库服务。迁移脚本会创建`.env`中`DATABASE_PATH`指定的数据库和目录。运行中的SQLite文件不得放在OneDrive等云同步目录；当前本机使用`C:\BigHeroData\big-hero.sqlite`。邀请码只在生成时显示一次，数据库只保存摘要。首次准备完成后，以后只需双击 `update-and-start-server.bat`：脚本自动检查GitHub版本、更新前备份数据库、安装有变化的依赖，然后迁移、编译并启动服务器。`start-server.bat`只启动当前已安装版本，不检查GitHub。本机访问`http://127.0.0.1:3000/game/`，其他已加入同一 ZeroTier 网络的电脑访问`http://服务器的ZeroTier地址:3000/game/`。若超过20个不同账号同时在线，第21个账号收到“服务器人数已满，请稍后登录”；同账号重新登录则替换旧连接，不额外占用名额。

失败处理：

| 情况 | 处理 |
|------|------|
| 数据库文件无法创建或打开 | 服务不进入可用状态；检查`.env`路径和目录写入权限 |
| 迁移执行失败 | 当前迁移事务回滚；修复原因后重新执行`npm run migrate` |
| 邀请码生成失败 | 不产生半条邀请码；确认迁移完成后重试 |
| 端口占用 | 修改`.env`中的`PORT`后重启，并用新端口打开`/game/`；浏览器自动同源连接，无需修改客户端地址 |
| GitHub暂时无法连接 | 自动更新脚本显示警告并启动当前已安装版本 |
| 仓库存在本地改动或不是`main`分支 | 为避免覆盖文件，跳过更新并启动当前版本；联系维护者检查 |
| 数据库备份失败 | 取消更新且不启动新版本，保留现有文件和玩家数据 |
| 远端历史不能安全快进 | 拒绝强制覆盖，保留当前版本并提示联系维护者 |

## 3. 数据备份

```powershell
npm run backup
```

该命令使用SQLite在线备份接口，把一致性快照写入`BACKUP_DIRECTORY`。服务器运行时不要直接复制`.sqlite`、`.sqlite-wal`和`.sqlite-shm`文件。当前备份目录为`C:\BigHeroBackups`；自动定时备份与恢复演练在N7完成。

## 4. Godot网页客户端

服务器直接发布`SERVER/public/game/`中的Godot 4.4 Web构建，这是唯一玩家客户端。游戏功能继续在`client/`中的Godot源码开发，修改后重新导出，不启动已停用的`web-client/`构建，也不单独发布桌面程序。服务器电脑只需Git和Node.js，不需要安装Godot。玩家电脑只需安装、加入并获准使用同一个ZeroTier网络，再使用新版Chrome或Edge打开网页，不需要安装证书，也不需要执行额外命令；服主需预先完成监听与防火墙配置。

本项目导出时必须保持`client/export_presets.cfg`中的`variant/thread_support=false`。无多线程构建不依赖`SharedArrayBuffer`，兼容工具会让普通HTTP跳过Godot模板多余的安全上下文拦截；HTTP环境没有`AudioWorklet`时，音频自动使用Godot自带的`ScriptProcessor`后备。若浏览器两种音频接口都不支持，则游戏仍可显示，但无声音。

Godot重新导出后执行：

```powershell
cd D:\onedrive\note\Game\Game-大勇者\SERVER
npm run web:patch
npm run check
```

兼容工具具备幂等检查：已处理的发布包不会重复修改；若导出模板结构改变、线程被开启或补丁缺失，检查失败并阻止误发布。浏览器客户端使用同源`/api/v1`和`/ws`，因此账号登录和实时连接自动指向玩家当前打开的ZeroTier地址，会话令牌不放进URL。

勾选“记住登录状态”时，浏览器不保存账号密码。服务端签发独立随机令牌，数据库只保存SHA-256摘要，浏览器使用`HttpOnly`、`SameSite=Strict` Cookie；成功恢复后令牌立即轮换。主动退出、改密、管理员重置密码、封号或删号会使长期令牌失效。同账号最多保留一个有效长期令牌，新浏览器重新勾选登录后旧浏览器需重新输入密码。

| 访问情况 | 结果 |
|------|------|
| 已加入并获准使用同一ZeroTier网络，地址和端口正确，服务器监听且防火墙放行 | 加载Godot客户端并连接同源账号服务 |
| 未加入ZeroTier网络、未授权、服务器离线或防火墙阻断 | 浏览器无法连接；服主检查网络与监听配置，不回退到公网地址 |
| Godot误导出为多线程版本 | `npm run web:check`失败；必须重新导出无多线程版本 |
| 未来改为真正公网开放 | 当前HTTP方案不适用；需配置可信HTTPS证书和WSS |

> 设计柱检验：Godot客户端复用原版地图、装备与战斗表现；同源单端口减少玩家和服主操作；失败状态明确且不静默降级，符合柱2、柱5与柱6。

## 5. 检查

```powershell
npm run check
npm audit --omit=dev
```

检查覆盖账号与角色输入、20/21人容量、同账号替换会话、30秒断线名额、记住登录签发/轮换/撤销、SQLite摘要存储、注册登录角色主流程、角色删除事务与拍卖引用保护、WebSocket聊天、拍卖交易守恒、断线后战斗状态恢复、损坏状态保护，以及服务端战斗和全部200级Boss生成。当前自动测试为65项，并已在Edge中验证Godot画布、HttpOnly Cookie和刷新自动恢复。已有测试不等于跨机验收；后续仍需在另一台ZeroTier电脑完成登录、聊天、拍卖和长期运行验证。

> 设计柱检验：服务端权威资产保护柱2与柱6；20人硬上限、单体部署和确定性失败处理控制维护成本，符合柱5。
