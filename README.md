# Big Hero Web

《大勇者》网页网络版单体仓库，面向最多20名玩家同时在线的个人服务器。玩家只需安装并加入同一个 ZeroTier 网络，然后在浏览器打开服务器地址即可进入 Godot 网页客户端。

## 目录

| 目录 | 内容 |
|------|------|
| `client/` | 唯一维护的Godot Web客户端源码、原版游戏内容和Web导出兼容工具 |
| `web-client/` | 已停用的原生网页原型，仅保留作历史对照，不参与服务器启动 |
| `SERVER/` | TypeScript服务端、SQLite迁移、网页静态文件与自动测试 |

## 开发与交付范围

自2026-09-16起，只开发、发布和验收Godot浏览器客户端与服务端。Godot是网页游戏的开发引擎，不再交付Windows等桌面原生客户端；玩家不需要安装Godot。首版支持电脑Chrome/Edge浏览器，手机完整适配不在当前范围。

继续复用`client/`中的原版UI、地图场景、逐格移动、装备、技能和战斗表现，不用`web-client/`中的手写网页原型替代游戏，也不擅自简化玩法、增加道具或改变数值。定案与现有代码不一致、浏览器能力不足或表现不明确时，先指出具体位置并讨论，不能自行换成简化方案。完整边界见仓库内《策划案/网页网络游戏改造总案【定案】.md》§3.3；已同步的策划案和《数值设计总表》随代码一并维护。

旧桌面入口与本地存档代码只保留作历史参考，不另行维护桌面兼容；可复用的规则回归继续保留，但浏览器功能必须用真实Web导出验证，编辑器运行成功不能替代网页验收。

> 设计柱检验：单一浏览器交付目标减少柱5的维护负担；保留原版Build和格子表现保护柱2与柱4，不以网页化为理由改变已确认玩法。

## 本地运行

服务器电脑首次部署：

```powershell
cd SERVER
Copy-Item .env.example .env
npm ci --include=dev --ignore-scripts
npm run migrate
npm run invite:create -- --count=5
```

之后关闭旧服务器窗口，双击 `SERVER/update-and-start-server.bat` 并保持窗口运行。脚本会自动检测GitHub版本；有更新时先备份数据库，再安全更新、安装变化的依赖、迁移、编译并启动。GitHub暂时不可用时会启动当前版本，本地项目文件有改动时则跳过更新以免覆盖。服务器本机访问 `http://127.0.0.1:3000/game/`；同一 ZeroTier 网络中的其他电脑访问 `http://服务器的ZeroTier地址:3000/game/`。不需要安装 Godot、不需要启动前端开发服务器，也不需要输入端口转发命令。

玩家页面由 Godot 4.4 无多线程Web导出生成，发布文件位于 `SERVER/public/game/`。Godot重新导出后，在 `SERVER` 目录执行 `npm run web:patch`，再执行 `npm run check`；兼容工具会保留HTTPS能力，同时允许无多线程版本通过 ZeroTier 私网HTTP启动。详细部署、测试和备份说明见[`SERVER/README.md`](SERVER/README.md)。

当前网页恢复 Godot 原版登录界面、9格透视地图、逐格移动、背包、装备、技能与战斗表现。账号、单角色创建/删除、20人在线上限和WebSocket会话由服务端提供；世界聊天、拍卖行以及玩法资产的服务端权威化已接入并通过本机浏览器联调，另一台ZeroTier电脑仍需现场验收。

## 安全边界

`.env`、SQLite运行库、备份、`node_modules`和Godot导入缓存均不进入Git；`SERVER/public/game/`中的Godot发布文件会进入Git，确保服务器电脑克隆后无需安装Godot即可启动。ZeroTier传输层本身提供端到端加密；当前无多线程Godot导出可使用HTTP和`ws://`。若日后改为真正公网部署，必须增加HTTPS/WSS反向代理。

> 设计柱检验：直接复用已验证的Godot客户端保护原版表现与规则一致性；单端口同源部署和自动兼容检查控制20人个人服务器的维护成本，符合柱2、柱5与柱6。
